# Task 8: AWS Observability

## 1. Objective

The objective of this task is to explore AWS Observability services, understand their purpose and usage, and learn how they help DevOps teams monitor infrastructure, applications, logs, metrics, traces, security events, and system health.

---

## 2. Introduction to AWS Observability

AWS provides a collection of monitoring and observability services that help organizations understand the health, performance, availability, and behavior of their applications and infrastructure.

AWS observability services can be used to:

- Monitor AWS resources and applications.
- Collect and analyze metrics.
- Collect and search application and system logs.
- Trace requests across distributed applications.
- Detect application performance issues.
- Monitor infrastructure health.
- Audit API activity.
- Track resource configuration and compliance.
- Visualize operational data.
- Troubleshoot production issues.

Observability helps DevOps teams understand not only that a system has a problem, but also why the problem is happening.

---

## 3. Monitoring vs Observability

### Monitoring

Monitoring focuses on predefined metrics, logs, and alerts.

Examples:

- CPU utilization is above 80%.
- Memory utilization is high.
- An EC2 instance is unhealthy.
- HTTP 5xx errors increased.

Monitoring answers:

> "Is the system working normally?"

### Observability

Observability provides deeper visibility into the internal state of a system using telemetry such as metrics, logs, and traces.

Observability helps answer:

> "Why is the system behaving this way?"

For example, if an application becomes slow, observability can help identify:

1. Which request is slow.
2. Which service caused the delay.
3. Which database query is responsible.
4. Which server or container experienced the issue.
5. What errors occurred during the request.

---

## 4. Three Pillars of Observability

The three primary pillars are:

### 4.1 Metrics

Metrics are numerical measurements collected over time.

Examples:

- CPU utilization.
- Memory usage.
- Request count.
- Network traffic.
- Error rate.
- Response time.

AWS CloudWatch is commonly used for collecting and monitoring metrics.

### 4.2 Logs

Logs contain detailed records of events generated by applications and infrastructure.

Examples:

- Application errors.
- Login events.
- HTTP requests.
- System messages.
- Container logs.

CloudWatch Logs and Amazon OpenSearch Service can be used for log collection and analysis.

### 4.3 Traces

Traces follow a request as it travels through different components of a distributed application.

Example:

```text
User Request
     |
     v
Load Balancer
     |
     v
Application
     |
     v
API Service
     |
     v
Database
```

AWS X-Ray can be used to trace requests and identify latency between application components.

## 20. Example Monitoring Workflow

Consider a web application running on AWS.

```text
                    Web Application
                          |
                          v
                       EC2
                          |
              +-----------+-----------+
              |           |           |
           Metrics       Logs       Traces
              |           |           |
              v           v           v
         CloudWatch   CloudWatch     X-Ray
                       Logs
              |           |
              |           v
              |      Logs Insights
              |
              v
          CloudWatch
           Alarm
              |
              v
           Alert
```

### Example incident

Suppose users report that the application is slow.

A DevOps engineer can:

1. Check CloudWatch metrics.
2. Identify increased CPU or latency.
3. Search application logs using Logs Insights.
4. Use X-Ray to trace slow requests.
5. Identify the affected service.
6. Investigate the root cause.
7. Resolve the issue.
8. Continue monitoring the application.

## 22. Conclusion

AWS provides a broad observability ecosystem that supports infrastructure monitoring, application monitoring, log analysis, distributed tracing, auditing, configuration monitoring, and visualization.

For DevOps teams, observability is important for maintaining reliable applications and quickly identifying and resolving production issues.

A combination of CloudWatch, X-Ray, CloudTrail, AWS Config, OpenTelemetry, Managed Prometheus, Managed Grafana, and OpenSearch can provide comprehensive visibility into AWS environments.

The key principle is:

```text
Collect → Monitor → Analyze → Detect → Troubleshoot → Improve
```
