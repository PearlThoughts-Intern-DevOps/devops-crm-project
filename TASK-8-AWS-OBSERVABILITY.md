\# Task 8 – AWS Observability



\## 1. Objective



The objective of this task was to explore AWS observability services and understand how they help monitor applications, infrastructure, logs, metrics, traces, and system health.



Observability helps DevOps teams understand what is happening inside an application or infrastructure by collecting and analyzing metrics, logs, and traces.



\---



\## 2. AWS Observability Services Explored



\### 2.1 Amazon CloudWatch



Amazon CloudWatch is the main monitoring and observability service in AWS.



It can be used to monitor:

\- EC2 instances

\- Applications

\- AWS services

\- System metrics

\- Logs

\- Alarms

\- Events



Important metrics include CPU utilization, network traffic, disk-related metrics, and application metrics.



\### 2.2 CloudWatch Metrics



CloudWatch Metrics are numerical measurements collected over time.



Examples:

\- EC2 CPU utilization

\- NetworkIn and NetworkOut

\- Request count

\- Error count

\- Latency



Metrics help identify performance problems and resource usage.



\### 2.3 CloudWatch Logs



CloudWatch Logs is used to collect and store logs from applications, servers, and AWS services.



Logs can help identify:

\- Application errors

\- Failed requests

\- System problems

\- Authentication issues

\- Debugging information



Log Groups are used to organize related logs.



\### 2.4 CloudWatch Logs Insights



CloudWatch Logs Insights allows logs to be searched and analyzed using queries.



It is useful when troubleshooting an application because specific errors, requests, or patterns can be searched without manually checking every log entry.



\### 2.5 CloudWatch Alarms



CloudWatch Alarms monitor metrics and perform actions when a defined threshold is reached.



Example:



If EC2 CPU utilization stays above 80%, an alarm can change to the ALARM state and send a notification through Amazon SNS.



\### 2.6 CloudWatch Dashboards



CloudWatch Dashboards provide a visual view of important metrics in one place.



A DevOps engineer can create a dashboard showing:

\- EC2 CPU usage

\- Network traffic

\- Application metrics

\- Error rates

\- Alarm status



\### 2.7 AWS X-Ray



AWS X-Ray helps trace requests through distributed applications.



It can help identify:

\- Slow services

\- Request latency

\- Application errors

\- Dependencies between services



X-Ray is especially useful for troubleshooting microservices and distributed applications.



\### 2.8 Amazon CloudWatch Application Signals



Application Signals helps monitor application performance and health.



It provides visibility into application behavior and important performance indicators such as latency, availability, and errors.



\### 2.9 CloudWatch Synthetics



CloudWatch Synthetics can run automated tests called canaries.



Canaries can periodically test application endpoints and verify that an application is available and responding correctly.



\### 2.10 CloudWatch RUM



CloudWatch Real User Monitoring (RUM) collects information about the actual user experience of a web application.



It can provide information about:

\- Page loading

\- JavaScript errors

\- User sessions

\- Performance



\### 2.11 Amazon Managed Service for Prometheus



Amazon Managed Service for Prometheus is a managed monitoring service compatible with the open-source Prometheus project.



It is useful for collecting and querying metrics, particularly in containerized and Kubernetes environments.



\### 2.12 Amazon Managed Grafana



Amazon Managed Grafana provides managed Grafana dashboards.



It can be used to visualize metrics and monitoring data from services such as CloudWatch and Prometheus.



\### 2.13 AWS Distro for OpenTelemetry (ADOT)



AWS Distro for OpenTelemetry is an AWS-supported distribution of OpenTelemetry.



It helps collect telemetry such as:

\- Metrics

\- Traces

\- Application information



The collected telemetry can be sent to supported AWS monitoring services.



\### 2.14 Amazon OpenSearch Service



Amazon OpenSearch Service can be used for searching, analyzing, and visualizing large amounts of data.



It can be useful for:

\- Log analytics

\- Application monitoring

\- Searching operational data

\- Creating visualizations

\## 3. Observability Pillars



The three main pillars of observability are:



\### Metrics

Numerical measurements that show system or application performance.



Example:

\- CPU utilization

\- Memory usage

\- Request count



\### Logs

Detailed records of events generated by applications and infrastructure.



Example:

\- Error messages

\- Application events

\- Authentication events



\### Traces

Information showing the path of a request through different components of an application.



Traces are especially useful for distributed applications and microservices.



\---



\## 4. EC2 Observability Example



During my AWS EC2 work, CloudWatch can be used to monitor the EC2 instance.



For an EC2 instance running Twenty CRM, useful monitoring information includes:



\- CPU utilization

\- Network traffic

\- Instance status

\- System health

\- Application/container logs



This can help identify whether the instance is under high resource usage or experiencing availability problems.



\---



\## 5. Example DevOps Observability Workflow



A typical observability workflow can be:



1\. Application runs on EC2 or containers.

2\. Metrics are collected by CloudWatch.

3\. Application and system logs are collected.

4\. Dashboards visualize important metrics.

5\. CloudWatch Alarms monitor important thresholds.

6\. SNS can be used for notifications.

7\. X-Ray or OpenTelemetry can help trace application requests.

8\. Engineers investigate problems using metrics, logs, and traces.



\---



\## 6. Why Observability is Important in DevOps



Observability helps DevOps teams:



\- Detect problems early

\- Troubleshoot application failures

\- Monitor infrastructure

\- Understand application performance

\- Identify resource bottlenecks

\- Reduce downtime

\- Improve reliability

\- Support production systems



Without observability, it is difficult to understand why an application or infrastructure component is failing.

\## 7. Key Learnings



From this task, I learned that AWS provides different observability tools for different requirements.



CloudWatch is the primary service for monitoring AWS resources, metrics, logs, alarms, and dashboards.



X-Ray and OpenTelemetry are useful for understanding application traces and distributed systems.



Prometheus and Grafana are useful for metrics collection and visualization, especially for containerized and Kubernetes workloads.



I also learned that metrics, logs, and traces complement each other. Using them together gives a better understanding of application and infrastructure health.

AWS observability services provide the tools required to monitor infrastructure and applications throughout their lifecycle.



As a DevOps engineer, understanding CloudWatch, logs, metrics, alarms, tracing, dashboards, and related observability tools is important for maintaining reliable and scalable applications.
