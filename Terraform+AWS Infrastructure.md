# Twenty CRM Deployment Using Terraform, AWS EC2, ECR, and Docker

## 1. Project Setup

The task started by creating a **proper Terraform project structure** to manage the AWS infrastructure required for deploying Twenty CRM.

The Terraform directory contained:

- `provider.tf` — Terraform and AWS provider configuration.
- `data.tf` — References to existing AWS resources such as the default VPC, subnet, and the existing EC2 IAM instance profile.
- `main.tf` — AWS resources created by Terraform, including ECR, Security Group, and EC2.
- `variable.tf` — Configurable Terraform variables.
- `terraform.tfvars` — Actual values for the configurable variables.
- `output.tf` — Important information returned after deployment.
- `.gitignore` — Prevented Terraform state, local configuration, and other generated files from being committed unnecessarily.

## 2. AWS Provider and Existing Resources

Terraform was configured to use the **AWS provider in the `us-east-1` region**.

Instead of creating networking infrastructure unnecessarily, the existing **default VPC and an existing subnet** were referenced through Terraform data sources.

The existing IAM instance profile provided by the administrator, **`EC2ECRPullRole`**, was also referenced rather than creating a new IAM role. This allowed the EC2 instance to obtain the required permissions for pulling images from Amazon ECR without storing IAM access keys on the instance.

## 3. Terraform Variables and Outputs

Configurable values were separated from the infrastructure definitions using Terraform variables.

Important variables included:

- AWS region
- EC2 instance type
- Amazon Linux 2023 AMI ID
- ECR repository name
- EC2 name
- Existing EC2 key-pair name
- SSH CIDR
- Twenty CRM application port

Terraform outputs were configured for important deployment information, including:

- Default VPC ID
- Selected subnet ID
- EC2 instance ID
- EC2 public IP
- ECR repository URL

## 4. Terraform Infrastructure Creation

The ECR repository was created using Terraform with **image scanning on push** enabled.

The EC2 instance was configured with:

- Amazon Linux 2023 AMI
- `t3.small` instance type
- Existing EC2 key pair
- Dedicated Security Group
- Existing `EC2ECRPullRole` IAM instance profile
- Public IP address
- 20 GB `gp3` root volume

## 5. Terraform Validation and Deployment

The Terraform configuration was formatted and validated before deployment.

The following commands were used:

```bash
terraform fmt
terraform init
terraform validate
terraform plan
terraform apply
```

`terraform plan` was used to review the resources Terraform intended to create before applying the configuration.

After approval, `terraform apply` created the required AWS infrastructure.

## 6. Building the Twenty CRM Docker Image

After the ECR repository was created, the **Twenty CRM Docker image was built locally** using the existing Dockerfile.

The image was built with:

```bash
docker build -t twenty:latest .
```

At this point, the image existed on the local machine but was not yet present in ECR.

## 7. Tagging and Pushing the Image to ECR

The ECR repository URL generated by Terraform was retrieved using the Terraform output.

The local Docker image was then tagged using the ECR repository URL.

Amazon ECR authentication was performed using the AWS CLI, followed by pushing the image to ECR.

The workflow was:

**Local Dockerfile → Local Docker Image → ECR Tag → ECR Authentication → Docker Push → Image Stored in ECR**

The image was pushed using the `latest` tag.

## 8. EC2 User Data and Automatic Deployment

EC2 User Data automated the application setup when the instance launched.

The startup process performed the following actions:

1. Updated the Amazon Linux packages.
2. Installed **Docker** and the AWS CLI.
3. Enabled and started Docker.
4. Added `ec2-user` to the Docker group.
5. Used the EC2 instance profile to authenticate with Amazon ECR.
6. Attempted to pull the Twenty CRM image.
7. Retried the image pull periodically if the image was not yet available.
8. Verified that the image was successfully downloaded.
9. Started the Twenty CRM Docker container.
10. Configured the container to restart automatically.

This retry mechanism handled the situation where EC2 started before the Docker image had been pushed to ECR.

## 9. Application Verification

After the image was available in ECR, the EC2 User Data process successfully pulled the image and started the Twenty CRM container.

The deployment was verified by connecting to the EC2 instance through SSH using the existing `.pem` key.

The Docker container was checked using commands such as:

```bash
docker ps
```

The application was also tested through the EC2 public IP and mapped application port:

```text
http://<EC2_PUBLIC_IP>:3000
```

This confirmed that the **Twenty CRM application was running successfully on EC2**.

## 10. Documentation and Issues

During implementation, AWS IAM permission restrictions were encountered. The IAM user initially received explicit denies for operations such as `ec2:CreateSecurityGroup` and `ec2:RunInstances`.

The issue was identified as an **AWS IAM authorization restriction rather than a Terraform configuration error**. The final deployment assumed that the required EC2 permissions were available and that the administrator-provided `EC2ECRPullRole` was available for ECR access.

## 11. Cleanup

After successful verification, the infrastructure created for the task was removed using:

```bash
terraform destroy
```

Terraform removed the resources it had created, including the **EC2 instance, Security Group, and ECR repository**.

Finally, AWS resources were verified to ensure that the infrastructure created for the exercise had been cleaned up successfully.
