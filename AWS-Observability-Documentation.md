Monitoring vs Observability



2.1 Monitoring



Monitoring focuses on predefined metrics, conditions, and alerts. Examples include CPU utilization above 80%, disk usage above 90%, an unhealthy EC2 instance, or HTTP 500 errors.



Monitoring helps answer: “Is something wrong?”



2.2 Observability



Observability goes deeper and helps understand why something is wrong. If an application becomes slow, observability can combine logs, metrics, traces, database latency, network activity, and recent infrastructure changes.



Key distinction: Monitoring tells us that a problem exists, while observability helps us understand the reason behind the problem.



3\. Three Major Pillars of Observability



3.1 Metrics



Metrics are numerical measurements collected over time.



Examples: CPU utilization, memory utilization, network traffic, request count, error count, response latency, disk utilization.



3.2 Logs



Logs contain detailed records of events generated by applications, operating systems, and AWS services.



Examples: Application startup messages, authentication failures, database timeouts, HTTP 500 errors.



3.3 Traces



Traces show the path of a request through different components of an application.



Examples: Client → API Gateway → Lambda → DynamoDB; useful for latency, failures, dependencies, and bottlenecks.



4\. Amazon CloudWatch



Amazon CloudWatch is one of the primary AWS observability and monitoring services. It provides capabilities for metrics, logs, alarms, dashboards, application monitoring, infrastructure monitoring, and log analysis.



5\. CloudWatch Metrics



CloudWatch Metrics are time-ordered numerical data points. Examples include EC2 CPU utilization, network traffic, S3 request counts, Lambda invocations and errors, and application latency.



A metric generally contains a metric name, namespace, dimensions, timestamp, value, and unit.



Metric: CPUUtilization

Instance: i-123456789

Value: 75%



6\. CloudWatch Logs



CloudWatch Logs is used to collect, store, monitor, and analyze log data from EC2, Lambda, ECS, applications, AWS services, and custom workloads.



Log Group: A collection of log streams. Example: /devops-crm/application



Log Stream: A sequence of log events from a particular source. Example: EC2-instance-i-123456789



7\. CloudWatch Logs Insights



CloudWatch Logs Insights provides interactive querying and analysis of log data. It is useful during incident investigation because engineers can quickly search large volumes of logs.

8\. CloudWatch Alarms



CloudWatch Alarms automatically monitor metrics and perform actions when predefined conditions are met.



Metric: EC2 CPU Utilization

Condition: CPU > 80%

Duration: 5 minutes

Action: Send notification



Common use cases: high CPU, high error rate, high latency, low disk space, and application failures.



9\. CloudWatch Dashboards



CloudWatch Dashboards provide a centralized visual view of metrics and monitoring information. A dashboard can display CPU utilization, network traffic, request counts, error rates, latency, Lambda metrics, and application metrics.

10\. CloudWatch Application Signals



CloudWatch Application Signals helps monitor application performance using application-centric metrics. It focuses on indicators such as availability, latency, errors, and service dependencies.



11\. AWS X-Ray



AWS X-Ray provides distributed tracing for applications. It helps analyze requests as they move through multiple services and identify slow services, failed requests, service dependencies, latency, errors, and bottlenecks.

12\. Amazon Managed Service for Prometheus



Amazon Managed Service for Prometheus is a managed monitoring service compatible with the open-source Prometheus project. It is widely relevant to Kubernetes, containers, and cloud-native applications.



13\. Amazon Managed Grafana



Amazon Managed Grafana is a managed service for creating dashboards and visualizing metrics and other observability data. It can visualize data from CloudWatch, Prometheus, AWS services, and other supported sources.



14\. AWS CloudTrail



AWS CloudTrail records AWS API activity and account activity. It helps answer who performed an AWS action, what action was performed, which resource was involved, and when the activity occurred.



CloudTrail is useful for auditing, security investigation, compliance, troubleshooting, and tracking changes.



Key distinction: CloudWatch focuses on monitoring and observability, while CloudTrail focuses on AWS API and account activity.



15\. VPC Flow Logs



VPC Flow Logs capture information about network traffic flowing through network interfaces in a VPC. They help investigate connectivity problems, rejected traffic, unexpected traffic, and network behavior.



16\. AWS Config



AWS Config continuously records and evaluates AWS resource configurations. It helps determine current configuration, configuration history, and compliance with defined rules.



17\. AWS Health Dashboard



AWS Health Dashboard provides information about AWS service events that may affect resources or accounts, including service disruptions, scheduled maintenance, account-specific events, and operational issues.



18\. AWS Distro for OpenTelemetry



AWS Distro for OpenTelemetry (ADOT) is an AWS-supported distribution of OpenTelemetry. OpenTelemetry is an open standard for collecting telemetry such as metrics, traces, and logs. ADOT can instrument applications and send telemetry to supported destinations.



19\. CloudWatch Synthetics



CloudWatch Synthetics allows engineers to create automated tests called canaries. Canaries simulate user interactions with an application and are useful for website monitoring, API monitoring, availability testing, and user-journey monitoring.



Open Website → Login → Open Dashboard → Check Response



20\. CloudWatch RUM



CloudWatch RUM (Real User Monitoring) collects client-side information from real users interacting with web applications. It provides insight into page-load performance, client-side errors, sessions, browser information, and application performance.



21\. CloudWatch Container Insights



CloudWatch Container Insights provides monitoring and observability for container environments such as Amazon ECS, Amazon EKS, and Kubernetes workloads. It provides information about CPU, memory, network, containers, and clusters.



22\. CloudWatch Lambda Insights



Lambda Insights provides enhanced monitoring information for AWS Lambda functions, including CPU, memory, network activity, cold starts, and invocation performance.



23\. CloudWatch Database Insights



CloudWatch Database Insights provides database performance monitoring and troubleshooting capabilities. It can help analyze workload, performance problems, and resource-intensive database activity.



24\. Amazon OpenSearch Service



Amazon OpenSearch Service is a managed service for search, log analytics, and observability use cases. It can be used to analyze logs, search large datasets, build visualizations, investigate application events, and perform security analytics.

28\. Practical Observability Troubleshooting Workflow



Step 1 — Detect: Use CloudWatch Metrics, Dashboards, and Alarms to identify that something is wrong.



Step 2 — Investigate Logs: Use CloudWatch Logs and Logs Insights to search for errors, exceptions, failed requests, authentication failures, and database errors.



Step 3 — Investigate Request Flow: Use X-Ray and Application Signals to identify slow or failing application components.



Step 4 — Check Infrastructure Changes: Use CloudTrail and AWS Config to determine whether a recent change caused the issue.



Step 5 — Investigate Network Problems: Use VPC Flow Logs to check whether network traffic is being accepted or rejected.



Step 6 — Check AWS Service Health: Use the AWS Health Dashboard to determine whether AWS itself is experiencing an issue.



Step 7 — Monitor Continuously: Use CloudWatch Dashboards, Alarms, Grafana, and Prometheus to maintain visibility and alerting.
Observability Best Practices



Monitor important metrics instead of collecting everything without purpose.



Centralize logs so they can be searched and analyzed efficiently.



Create meaningful, actionable alarms and avoid excessive alert noise.



Use dashboards for important applications and infrastructure.



Use distributed tracing for microservices and serverless applications.



Track infrastructure changes using CloudTrail and AWS Config.



Protect observability data with appropriate IAM access controls.



Define log retention policies based on business, troubleshooting, and compliance requirements.



Use automation for alerting and incident-response workflows.



Combine metrics, logs, traces, configuration data, and network information for a complete view.



31\. Key Learnings



The main learning from this task is that AWS observability is not limited to checking whether an EC2 instance is running. Effective observability requires visibility across infrastructure, applications, logs, metrics, traces, network activity, configuration, and API activity.



Metrics provide numerical information about system performance.



Logs provide detailed information about application and infrastructure events.



Traces show the flow of requests across distributed applications.



CloudWatch provides core monitoring and observability capabilities.



Logs Insights is useful for investigating large amounts of logs.



CloudWatch Alarms can automatically detect threshold-based problems.



CloudWatch Dashboards provide centralized visibility.



Application Signals provides application-centric performance insights.



X-Ray helps identify application bottlenecks.



CloudTrail provides visibility into AWS API activity.



VPC Flow Logs provide network-level visibility.



AWS Config helps track and evaluate resource configurations.



The AWS Health Dashboard helps identify AWS service-related issues.



Prometheus and Grafana are important for cloud-native observability.



OpenTelemetry provides a standardized approach to collecting telemetry.



Observability services complement one another rather than simply replacing one another
Conclusion



AWS provides a broad set of observability services that allow DevOps engineers to monitor infrastructure, applications, networks, configurations, user experience, and AWS account activity.



The key takeaway is that observability gives DevOps teams the visibility required to detect problems, investigate root causes, improve application performance, and maintain reliable AWS infrastructure.



Different AWS services provide visibility at different levels. Combining metrics, logs, traces, configuration data, network information, and API activity gives a more complete picture of an AWS environment.
