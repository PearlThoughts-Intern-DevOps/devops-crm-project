AWS Observability – Task 8
1. Introduction

AWS Observability is used to monitor, understand, and troubleshoot AWS infrastructure and applications. It helps us identify performance issues, errors, security activities, and configuration changes.

The main components of observability are:

Metrics – Numerical information about system performance, such as CPU utilization.
Logs – Records of events, errors, and activities generated by applications and systems.
Traces – Information about how a request travels through different services.

AWS provides multiple services to collect, monitor, analyze, and visualize this information.

2. Amazon CloudWatch

Amazon CloudWatch is the primary monitoring and observability service in AWS.

It helps monitor AWS resources, applications, and infrastructure. CloudWatch provides features such as metrics, logs, alarms, dashboards, and log analysis.

Example: We can use CloudWatch to monitor the CPU utilization of an EC2 instance and identify whether the instance is under heavy load.

3. CloudWatch Metrics

CloudWatch Metrics are numerical measurements used to monitor the performance and health of AWS resources and applications.

Some common metrics include:

EC2 CPU utilization
Network traffic
Request count
Error count
Application latency

Metrics can be displayed using dashboards and can also be used to create alarms.

Example: If the CPU utilization of an EC2 instance continuously goes above 80%, we can create an alarm to notify the team.

4. CloudWatch Logs

CloudWatch Logs is used to collect, store, and analyze logs from applications and AWS resources.

Logs are useful for troubleshooting application errors and understanding what happened inside a system.

CloudWatch Logs uses:

Log Groups – Groups of related logs.
Log Streams – Sequences of log events from a particular source.
Log Events – Individual log entries.

Example: An application running on an EC2 instance can send its application logs to CloudWatch Logs, allowing us to investigate errors without manually checking the server.

5. CloudWatch Alarms

CloudWatch Alarms monitor metrics and take action when a defined condition is met.

For example:

CPU Utilization > 80%


When this condition continues for the configured period, the alarm can change its state and trigger an action, such as sending a notification.

CloudWatch Alarms help with:

Monitoring
Notifications
Automated responses
Detecting performance issues
6. CloudWatch Dashboards

CloudWatch Dashboards provide a visual representation of monitoring information.

We can create dashboards containing:

CPU utilization
Network usage
Request counts
Error rates
Alarm status

Dashboards help teams monitor multiple resources from a single location.

7. CloudWatch Logs Insights

CloudWatch Logs Insights is used to query and analyze log data.

Instead of manually checking large amounts of logs, we can use queries to find specific information such as errors, requests, or unusual activity.

It is useful for troubleshooting and identifying application problems.

8. AWS X-Ray

AWS X-Ray is a distributed tracing service.

It helps us understand how requests move through different components of an application.

For example:

User
  ↓
Application
  ↓
API
  ↓
Database


X-Ray can help identify which part of the application is slow or causing errors.

It is especially useful for microservices and distributed applications.

9. AWS CloudTrail

AWS CloudTrail records activities and API calls made in an AWS account.

It helps answer questions such as:

Who performed an action?
What action was performed?
When was it performed?
Which AWS resource was affected?

CloudTrail is commonly used for auditing, security investigations, and tracking changes.

Example: If an EC2 instance is terminated unexpectedly, CloudTrail can help identify the API activity related to that action.

10. AWS Config

AWS Config is used to monitor and track the configuration of AWS resources.

It provides information about resource configurations and changes over time.

AWS Config can help with:

Configuration monitoring
Compliance
Change tracking
Resource management

Example: We can use AWS Config to identify whether an AWS resource has changed from its expected configuration.

11. Amazon Managed Service for Prometheus

Amazon Managed Service for Prometheus is a managed monitoring service compatible with Prometheus.

It can collect and query metrics from applications and infrastructure.

It is useful for environments that use containers, Kubernetes, and Prometheus-compatible metrics.

AWS manages the infrastructure, so teams do not need to manage the Prometheus servers themselves.

12. Amazon Managed Grafana

Amazon Managed Grafana is a managed dashboard and visualization service.

It can be used to create dashboards from monitoring data and display metrics in an easy-to-understand format.

It is useful for:

Infrastructure monitoring
Application monitoring
Metrics visualization
Creating operational dashboards
13. Amazon OpenSearch Service

Amazon OpenSearch Service can be used to search, analyze, and visualize large amounts of operational data.

It is commonly useful for log analysis and troubleshooting.

For example:

Application
    ↓
Logs
    ↓
OpenSearch
    ↓
Search and Analysis


This helps teams quickly search through logs and identify problems.

14. AWS OpenTelemetry

OpenTelemetry is used to collect telemetry data from applications.

Telemetry can include:

Metrics
Logs
Traces

It provides a standard way to collect observability data and can be useful for modern distributed applications and microservices.

15. Metrics, Logs, and Traces
Type	Purpose	Example
Metrics	Measure system performance	CPU = 75%
Logs	Record events and errors	Application error
Traces	Track request flow	API → Service → Database

Using metrics, logs, and traces together gives a better understanding of an application's health and behavior.

17. What I Learned

From exploring AWS Observability services, I learned that monitoring is more than just checking CPU and memory.

Different AWS services provide different types of visibility:

CloudWatch helps monitor resources and applications.
CloudWatch Logs helps collect and analyze logs.
CloudWatch Alarms helps detect problems automatically.
X-Ray helps understand request flow and application performance.
CloudTrail helps track AWS API activities.
AWS Config helps monitor resource configurations.
Prometheus and Grafana are useful for metrics monitoring and visualization.
OpenSearch helps with log search and analysis.
OpenTelemetry provides a standard way to collect telemetry data.

The combination of metrics, logs, and traces provides better visibility into an application's behavior and helps teams troubleshoot issues more efficiently.

18. Conclusion

AWS provides a wide range of observability services for monitoring infrastructure, applications, and AWS activities.

CloudWatch is the main monitoring service, while services such as X-Ray, CloudTrail, AWS Config, Prometheus, Grafana, OpenSearch, and OpenTelemetry provide additional capabilities.

By using these services together, teams can detect issues, investigate problems, monitor performance, track changes, and improve the reliability of applications.
